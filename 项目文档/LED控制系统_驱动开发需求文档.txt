# LED控制系统 - 驱动开发需求文档

## 1. 项目概述

本项目是基于RK3588开发板的LED控制系统，支持Android应用和ADB命令双控制模式，实现对Work灯的开关、亮度调节和模式切换功能。系统采用分层架构设计，支持自定义驱动与sysfs回退的双控制模式，确保在各种环境下的稳定性和兼容性。

## 2. 应用功能

### 2.1 应用控制功能
- **模式切换**：支持常亮模式、呼吸灯模式、闪烁模式
- **开关控制**：一键开启/关闭LED灯
- **亮度调节**：在常亮模式(work灯开启状态下)下可调节亮度（0-255）(app当work灯处于开启模式的时候最低亮度调节为0会自动设置成1防止灯熄灭造成work灯被同步机制识别为关闭状态)
- **状态同步**：UI显示与硬件状态实时同步(持续检测检测到变化后刷新)
- **智能亮度管理**：呼吸灯/闪烁模式下自动锁定亮度(只是在前端界面上锁定,实际上还是会一直0和255来回跳)
- **启动状态读取**：应用启动时自动读取并恢复上次退出时记录的 Work 灯开关状态、亮度值及模式，确保用户重启后无需重复设置。
- **关闭状态记录**：应用正常退出（包括主动关闭、系统回收、异常崩溃）时，立即将当前 Work 灯的开关状态、亮度值及模式写入本地持久化存储（SharedPreferences 或文件），下次启动时优先加载；若驱动层状态被外部 ADB 命令修改，应用下次激活时检测到差异后自动同步并更新本地记录。

### 2.2 ADB命令控制功能
- **模式切换命令**：
  - 呼吸灯模式：`adb shell "echo 'heartbeat' > /sys/class/leds/work/trigger"`
  - 常亮模式：`adb shell "echo 'default-on' > /sys/class/leds/work/trigger"`
- **开关控制命令**：
  - 开启LED：`adb shell "echo 255 > /sys/class/leds/work/brightness"`
  - 关闭LED：`adb shell "echo 0 > /sys/class/leds/work/brightness"`
- **状态查询命令**：
  - 查看模式：`adb shell "cat /sys/class/leds/work/trigger"`
  - 查看亮度：`adb shell "cat /sys/class/leds/work/brightness"`

## 3. 技术实现

### 3.1 应用架构
- **开发语言**：Java + C++
- **开发框架**：Android Studio
- **跨进程通信**：
  - 机制：使用Android系统隐式AIDL机制，无需显式编写AIDL文件
  - 实现：系统自动为本地Binder生成AIDL相关代码，处理跨进程通信
  - 进程配置：
    - MainActivity：运行在默认进程
    - HardwareTestActivity：运行在独立进程（:test）
    - RK3588HardwareService：标记为exported=true，允许跨进程访问
- **硬件通信**：
  - 应用层：Java代码通过JNI调用原生方法
  - 原生层：C++代码优先尝试访问字符设备节点 `/dev/zhangsan_led`，只有在不可访问时才回退到sysfs方式
  - 驱动层：
    - 优先：使用自定义字符设备驱动
    - 回退：使用Linux内核自带的LED驱动框架，通过sysfs接口提供访问
- **状态监控**：定期检测硬件状态，保持UI与硬件同步
- **数据传输**：LEDState类实现Parcelable接口，支持跨进程传输

### 3.2 驱动适配架构
- **核心原则**：保持接口一致性，仅在JNI层进行驱动适配，上层应用代码无需修改
- **分层适配策略**：
  - JNI层：处理底层硬件通信细节，易于适配新驱动
  - 服务层：统一硬件控制接口，隔离底层变化
  - UI层：用户交互和显示，独立于硬件实现
- **双模式保留**：继续支持"自定义驱动+sysfs回退"的双控制模式，确保系统稳定性

### 3.2 硬件访问方式
应用采用双层访问机制，优先使用字符设备节点，只有在不可访问时才回退到sysfs方式：

#### 1. 优先：字符设备节点方式
- **设备节点路径**：`/dev/zhangsan_led`
- **访问方式**：通过open()、ioctl()等系统调用访问
- **控制命令**：
  - LED_SET_POWER：设置LED电源状态
  - LED_SET_BRIGHTNESS：设置LED亮度
  - LED_GET_STATE：获取LED状态

#### 2. 回退：sysfs文件系统方式
应用通过sysfs文件系统访问LED设备，主要使用以下设备节点：
- `/sys/class/leds/work/trigger`：用于切换LED模式
- `/sys/class/leds/work/brightness`：用于调节LED亮度
- `/sys/class/leds/work/max_brightness`：用于获取最大亮度值

### 3.3 驱动适配最佳实践
- **接口一致性**：无论使用何种驱动，最终传递给应用层的数据必须保持统一的`LEDState`格式
- **数据格式转换**：在JNI层将新驱动返回的原始数据转换为统一的`LEDState`格式
- **模式名称映射**：当驱动返回的模式名称与APP预期不一致时，使用映射表进行转换
- **错误处理兼容**：保持错误码和异常情况处理方式一致

## 4. 驱动开发需求

### 4.1 硬件相关信息
- **开发板型号**：RK3568/RK3588开发板
- **LED名称**：Work灯
- **LED类型**：单色LED

### 4.2 设备节点需求
驱动需要创建以下设备节点：
- **字符设备节点**（自定义驱动）：`/dev/zhangsan_led`
- **sysfs节点**：
  - 主路径：`/sys/class/leds/work/`
  - 子节点：
    - `trigger`：用于切换LED模式
    - `brightness`：用于调节LED亮度（0-255）
    - `max_brightness`：返回最大亮度值（固定为255）

### 4.3 支持的模式
驱动需要支持以下LED模式：
- **常亮模式**（default-on）：LED持续亮着
- **呼吸灯模式**（heartbeat）：LED以呼吸节奏亮灭
- **闪烁模式**（timer）：LED以固定频率闪烁

### 4.4 权限设置
- **设备节点权限**：
  - 所有者：root
  - 组：root
  - 权限：rw-rw-rw-（或根据实际安全需求调整）

### 4.5 驱动实现要求
1. 驱动需要符合Linux内核驱动规范
2. 支持sysfs接口，与标准LED驱动框架兼容
3. 确保设备节点在系统启动时自动创建
4. 支持热插拔（如果需要）
5. 提供清晰的ioctl命令接口，支持LED状态的获取和设置
6. 返回的模式名称应与应用预期保持一致，或提供明确的映射关系

### 4.6 驱动适配指南

#### 4.6.1 设备节点与指令适配
1. **更新设备节点路径**：修改`LED_DEVICE_NODE`宏定义
   ```cpp
   // 示例定义
   #define LED_DEVICE_NODE "/dev/new_led_driver"
   ```

2. **调整控制指令**：更新`ioctl`命令或通信方式
   ```cpp
   // 示例命令定义
   #define IOCTL_GET_LED_STATE _IOR(LED_MAGIC, 0, led_state_t)
   #define IOCTL_SET_LED_POWER _IOW(LED_MAGIC, 1, int)
   ```

#### 4.6.2 数据格式转换
在`getLEDState()`函数中，将新驱动返回的原始数据转换为统一的`LEDState`格式：

```cpp
// 假设新驱动返回的数据结构
struct new_led_state {
    int is_on;
    int level;
    char mode_str[20];
};

// 转换为LEDState对象
LEDState* javaLedState = (LEDState*)env->NewObject(ledStateClass, constructor);
env->SetBooleanField(javaLedState, powerOnField, new_state->is_on);
env->SetIntField(javaLedState, brightnessField, new_state->level);
env->SetObjectField(javaLedState, modeField, env->NewStringUTF(new_state->mode_str));
```

#### 4.6.3 模式名称映射
当驱动返回的模式名称与APP预期不一致时，添加模式映射表：

```cpp
// 模式名称映射表
const std::map<std::string, std::string> modeMapping = {
    {"breathing", "heartbeat"},  // 驱动返回"breathing" -> 映射为"heartbeat"
    {"pulse", "heartbeat"},      // 驱动返回"pulse" -> 映射为"heartbeat"
    {"blink", "timer"},          // 驱动返回"blink" -> 映射为"timer"
    {"on", "default-on"}         // 驱动返回"on" -> 映射为"default-on"
};

// 应用映射
std::string modeStr(originalMode);
auto it = modeMapping.find(modeStr);
const char* finalMode = (it != modeMapping.end()) ? it->second.c_str() : originalMode;
```

## 5. 测试与验证

### 5.1 基本功能测试
1. **检查设备节点**：
   ```bash
   adb shell ls -la /sys/class/leds/work/
   # 检查自定义驱动节点
   adb shell ls -la /dev/zhangsan_led
   ```

2. **开启LED**：
   ```bash
   adb shell echo 255 > /sys/class/leds/work/brightness
   ```

3. **关闭LED**：
   ```bash
   adb shell echo 0 > /sys/class/leds/work/brightness
   ```

4. **切换到呼吸灯模式**：
   ```bash
   adb shell echo 'heartbeat' > /sys/class/leds/work/trigger
   ```

5. **查看当前模式**：
   ```bash
   adb shell cat /sys/class/leds/work/trigger
   ```

6. **查看当前亮度**：
   ```bash
   adb shell cat /sys/class/leds/work/brightness
   ```

### 5.2 应用功能测试
1. 安装Android应用：
   ```bash
   adb install app-debug.apk
   ```

2. 运行应用，测试以下功能：
   - 开关控制
   - 模式切换
   - 亮度调节
   - 状态同步

### 5.3 驱动适配测试
1. **功能验证**：
   - 电源控制：验证LED开关功能正常
   - 亮度调节：验证亮度调节范围和精度
   - 模式切换：验证常亮、心跳、闪烁模式切换正常
   - 状态同步：验证硬件状态变化能正确同步到UI

2. **兼容性测试**：
   - 有驱动场景：验证自定义驱动正常工作
   - 无驱动场景：验证sysfs回退机制正常工作
   - 驱动切换：验证在驱动加载/卸载过程中系统稳定性

3. **模式名称映射测试**：
   - 测试不同模式名称的映射转换
   - 验证模式切换和状态显示的一致性
